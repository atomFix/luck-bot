# 多声纹后台聆听与纯表情回应

日期：2026-10-24（Asia/Shanghai）
状态：交互方向已确认；本书面设计待用户审阅。尚未实现、安装新模型、录入声纹或更新固件。

## 已确认的目标

用户选择：自动听完并理解已录入人的话，只回应表情；说唤醒词才语音聊天。后台支持多个声纹。听到说话时眼睛平滑变成固定竖眼，聆听结束后根据意思回应，未聆听时保持专注。无声等待应更长且可设置。

第一版不判断一句话是否在对设备说。已录入的人在与他人交谈时也可能触发表情，这是本版明确的行为边界。声纹匹配在 Mac 本地，内容识别和语义分析继续使用已配置 ASR 与 DeepSeek。

## 代码基线与当前限制

- 当前提交 `eaccf16`，安装版可通过“你好小智”唤醒；仍有一次真实第三轮 `no_speech` 间歇失败未定位，不能作为已解决问题。
- `companion/src/voice/endpoint.ts` 已有本地 Silero VAD；无语音10秒超时，单次最长30秒。它判断是否在说话，不识别说话人。
- `hardware/esp32-bringup/companion/server.cc::OnWake` 才启动采音；板端单次采集有30秒上限。仅修改 Mac 超时不能实现持续背景聆听。
- `VoicePipeline.audio()` 默认进入语义、回复和合成；现有 `speak:false` 只关闭声音，仍会生成文字回复，需要新的纯表情处理路径。
- `character/eyes_model.cc` 当前只在 neutral 情绪下应用聆听眼型，并轮换三种；上一轮情绪可能覆盖聆听视觉，需要调整优先级。
- 现有 TLS、配对、控制者租约、序号/截止时间、手动优先级和回滚流程继续使用。

## 路线与选择

| 路线 | 能力与代价 | 选择 |
| --- | --- | --- |
| 仅唤醒后验证声纹 | 改动小，不会主动回应日常说话 | 不满足本次已选交互 |
| Mac 常驻本地 VAD＋声纹，匹配后才调用云端 | 支持主动表情；需要连续音频、分句和声纹管理 | 采用 |
| 先将全部声音送云端再判断身份 | 接入简单，但不满足本地先筛选的意图 | 不采用 |

不引入第二套聊天服务。现有 Node/TypeScript 常驻程序负责编排；本地声纹通过独立原生 helper 封装 sherpa-onnx 的 speaker embedding 提取能力，CPU运行。选择官方支持的中文16k说话人模型用于本机可行性验证；模型文件、许可证与精确SHA256通过检查后才进入正式包，不自动下载未验证的“最新”版本。

官方能力参考：[sherpa-onnx Speaker Identification](https://k2-fsa.github.io/sherpa/onnx/speaker-identification/index.html)。当前只查证其提供该能力，未验证本机模型速度、准确率或打包。

## 两种处理模式

### 背景表情

开启后台聆听且至少有一名启用的声纹时：

1. ESP32持续发送16kHz单声道PCM，Mac本地VAD检测语音，静音不调用云端。
2. 检测到持续语音即平滑变为固定竖眼，采集一句话，保留短预卷避免吃掉开头。
3. 句尾停顿后在本地提取声纹，与所有启用档案比较。未知、不确定、过短或多人重叠的片段放弃，恢复专注。
4. 匹配通过后才调用ASR，再调用DeepSeek表情分析，等待真实设备应用确认。
5. 不生成聊天回复，不调用TTS，不修改有声聊天历史。后台表情使用独立、按说话人隔离的有限语义上下文。
6. 表情保持模型给定且协议允许的时长后恢复专注；下一次真实说话立即进入竖眼。

匹配是概率判断；“不确定则忽略”表示保守处理，不承诺零误识别。首版声纹不是登录、设备授权或执行命令的凭据。

### 唤醒聊天

- 唤醒词或现有BOOT操作进入一轮有声聊天，保留ASR→表情→回复→TTS流程。
- 开启声纹筛选且已有启用档案时，该轮也先进行声纹匹配，再将语音发送云端；无声纹时保留当前唤醒聊天能力，背景表情不能开启。
- 一轮结束后恢复背景表情模式；不将一次唤醒视为永久有声聊天。
- 本机/板端播放期间暂停背景处理并丢弃回声尾音，避免设备回复自触发。首版不承诺播放时免唤醒全双工打断；BOOT和现有interrupt始终可停止播放。
- 后台任务不能抢占聊天、手动表情或系统关键提示；唤醒聊天取消尚未完成的后台任务，旧结果不得在聊天后重新显示。

## 时间与视觉规则

| 项目 | 设计值与含义 |
| --- | --- |
| 唤醒后无声等待 | 默认20秒，可设5–60秒；到期正常回专注，不以后台错误轰炸UI |
| 句尾静音 | 默认约1秒，可设0.6–2秒；只延长等待开口，不强迫每句说完再等20秒 |
| 背景静音 | 可无限等待，没有每10/20秒一次的no_speech异常或云端请求 |
| 单句上限 | 30秒；超过则放弃该句，等待明确静音后重置，不把长谈话切成连续付费请求 |
| 预卷 | 最多500毫秒，仅内存 |
| 排队 | 最多一个在处理、一个候选；拥塞丢弃更旧候选，禁止无限排队或并行付费 |
| 云端调用节流 | 每台设备最多每3秒启动一个后台轮次，每分钟最多10轮；默认不重试后台付费失败 |
| 模型返回表情 | 仍遵守现有300–3000ms范围，过期回专注 |

用户声音被本地VAD判为语音时进入竖眼，此时身份尚未确认，所以陌生人也可能短暂触发聆听外观，但不会在匹配失败后调用云端。若要连聆听外观也只对熟悉的人触发，需要等待身份判断，会增加反馈延迟，本版优先及时聆听反馈。

视觉优先级：系统关键提示／手动控制 → 当前有效聆听竖眼 → 语义表情 → 专注。竖眼覆盖上一轮残留情绪，保留平滑过渡与自然眨眼；不轮换聆听眼型、不随机切到其他闲置表情。断连不继续伪装正在聆听。

## 音频协议和固件改动

新增需owner权限的“后台聆听开关”和明确能力协商。旧固件不支持时后台开关不可启用，并显示需要更新；现有唤醒路径仍可使用。

背景音频流与对话turn分离：独立stream_id、连续frame_seq、采集代次和boot/session约束。协议以新的背景流事件声明来源，不能将既有v1所有音频无差别当作唤醒聊天。16k/mono/PCM16/20ms载荷继续使用；约32KB/s有效PCM，实际TLS开销和性能必须实测。

背景静音不会不断增加聊天turn；只有接受新的处理轮次才分配turn。切换模式、断连、租约过期、撤销、重启、禁用后台、录入结束均停止原流，清空旧预卷／候选／推理结果。新会话不能复用旧音频。后台流启停不需要重新配对，也不更改NVS中的Wi-Fi或模型配置。

当前30秒限制拆为“单句长度限制”，不再作为背景连接寿命；20秒可配置的开口等待由Mac负责，板端保留租约失联停止和有界队列。保留现有音频任务与唤醒检测，不同时启动相互冲突的AFE消费者；其兼容性是固件验收项。

## 声纹档案与本机设置

设置新增“后台表情”总开关、当前运行/暂停/故障状态、上述时间配置，以及声纹列表。每个档案有本地名称、启用状态、录入质量结果和删除入口。后台聆听为显式开启；首次安装和无档案时关闭。

录入从设置中主动开始，使用开发板麦克风，每人3段、每段5–8秒自然说话；录入期间暂停正常背景/聊天处理，不进行ASR或任何云端请求。检测静音、截幅、过短片段与相互不一致样本，质量不合格要求重新录该段，不能保存一个看似有效的空档案。取消录入或离线立即丢弃临时录音。

只持久化必要的声纹向量、模型版本、质量信息和名称；原始音频仅在内存，用后丢弃。向量用独立Keychain密钥进行认证加密，数据文件仅当前用户可读写；模型升级不能静默混用旧向量，需明确兼容或重新录入。删除档案同时删除内存匹配状态和对应语义上下文。最多支持10个启用档案，超出不静默截断。

匹配同时检查最佳分数是否过线以及与次佳档案的间隔；阈值通过实际麦克风的本人/陌生人/距离样本校准，不能照搬一个未经验证的通用数字。短句不足以可靠判断则忽略，不为了“每句话都有反应”而降低到明显误匹配。

多人重叠、音乐和电视声不保证可分离，首版不做说话人分离。可判定的混合/低质量片段不进入云端；无法保证识别所有重叠。录音回放也可能匹配，不提供活体检测或声纹认证承诺。

## 故障、资源和API边界

本地模型未加载、版本不符或推理失败时暂停后台并显示可行动错误，禁止跳过声纹直接调用云端。没有声纹、没有匹配、纯噪声、超长片段和关后台的静音期均为零云端请求。

匹配成功的一句后台语音最多一次ASR与一次表情分析，不产生reply/TTS请求；供应商鉴权或余额失败暂停后台云端处理，等待用户修正。原有明确唤醒聊天的重试策略单独保留。

PCM以最大30秒单句＋500ms预卷为界，约976KB，不落盘。推理并发为1，后续样本有界；原生helper按固定本地管道交换PCM与数值，不监听网络端口。声纹和姓名不发给DeepSeek/ASR，背景上下文有限且按人隔离；诊断仅保存轮次、阶段耗时、匹配成功/不确定等枚举和资源计数，不保存音频、识别文本、向量或姓名。

设置关闭后台、退出应用或释放设备，必须实际停止板端背景采音。网络重连后仅在用户已开启且声纹可用时恢复，不自动切换到小智云。

## 验证、实施顺序和回滚

1. 先增加失败轮次的本地VAD数值/时序诊断，区分现有间歇漏检与新声纹拒绝；不以一次成功声纹样本宣布原问题修复。
2. 本机声纹可行性验证：固定模型和许可证，实际16k输入，已录入/陌生/短句/静音样本，记录拒识与误匹配；M系Mac目标单句声纹处理p95≤500ms，但未经实测不能宣称达到。未达到则报告，不能偷偷改云端声纹或直接放行。
3. 实现后台流、句子分段、档案存储/录入、纯表情路径与UI配置，各自有取消、边界与故障测试。
4. 验证纯表情路径只调用ASR/reaction；未匹配零云端调用。校验多档案、删除、模型不符、取消/重启、无声20秒/长静音、30秒上限与队列限制。
5. 眼型验证：上一轮任意情绪都能被竖眼覆盖，句尾解除后语义表情生效，未知语音回专注，手动/关键提示优先，保持既有像素与625过渡测试。
6. 分开验收录入本人、其他已录入者、未录入者和播放回声；声纹样本需用户在明确录入步骤提供，不能用自动TTS冒充真人声纹准确率验证。
7. 重新做真实10轮/10分钟，包括背景表情与唤醒有声聊天交替，记录屏幕FPS、堆低水位、音频连续性、ASR/表情/声纹耗时、重启/看门狗。性能目标保持25–27FPS，低于24FPS需调查。未完成如实保留pending。
8. 保留现有安装包及精确固件基线、配对、Keychain和私有备份。刷写前重新确认实际OTA，仅更新应用槽，不擦除NVS/分区/模型。可独立关闭背景并回到当前唤醒模式；必要时回滚完整应用和应用槽。

上述顺序不等于已审阅的实施计划。按brainstorming流程，本书面设计确认后才编写具体实现计划；不发布公网服务或暴露新的设备端口。
